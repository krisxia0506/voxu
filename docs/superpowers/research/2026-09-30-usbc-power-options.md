# 单 USB-C 自动充电：模块调查与设计约束

日期：2026-09-30。状态：选型证据，不是可直接照焊的接线说明。

用户已确认主要连接 **MacBook 自带 USB-C**，要求接电脑充电并刷机、接充电器充电、无需切换。仍保留 ESP32 开发板及其接口。具体 MacBook 型号、端口实际电流声明尚未测量；不能把“USB-C”本身当作已授权 3 A。

## 1. 当前优先调查的连接方式

保留原 CH340 的 D+/D− 和下载电路，在原接口的 CC1/CC2 上加入电源能力识别；识别控制和充电电源路径独立于 ESP32 运行。这样关机或电池耗尽时仍可以启动充电。

```text
原 USB-C D+/D− ────────────────── 原 CH340 → ESP32 刷机
原 USB-C CC1/CC2 ── CC 检测 ────── 输入限流 / 充电输入使能
原 USB-C VBUS ───── 检测电路电源
               └── 负载分配充电器 ── 升压 → 原板 VIN
                         ↕
                       保护电池
```

该路径需要确认原板两个 CC 焊点，并按检测芯片要求移除原有 Rd；不能在原有 5.1 kΩ 下拉旁再并联一套。仅修改 VBUS 不足以接入 CC 检测。CC 控制器必须固定为受电端，不能默认 DRP 或向电脑输出电源。

若只能取得默认 USB 电流声明，仍需普通 USB 枚举预算处理；CC 方案不能把这个分支偷偷当成允许大电流。MacBook 的实测声明将决定是否需要补充该分支的实现。USB-A 转 C、扩展坞和休眠后的行为不能由 MacBook 直连结果推断。

## 2. 已核对的候选

| 候选 | 已确认能力 | 对本项目的结论 |
| --- | --- | --- |
| Adafruit BQ24074 #4755 + PowerBoost Basic #2030 | 负载分配、独立充电与升压；BQ EN1/EN2 可控制输入模式 | 可保留作为电源路径，但不提供 USB 电源识别 |
| Adafruit HUSB238 #5807 | 固定跳线选择电压/电流，默认 5 V；24.5 × 20.2 × 4.9 mm；数据线引出 | 不能把输出有电当作合同成立；暂不采用“输出直接接充电器即完成自动识别”的方案 |
| MIKROE-6939 USB-C Power 2 Click | PTN5150A CC 检测、非 I²C 输出、NX5P3090 电源开关；57.15 × 25.4 mm | 可作为硬件自动检测的现成模块候选；有额外电源与改焊要求，尚未冻结进 BOM |
| SparkFun BOB-13263 FT231X Breakout | USB UART 全握手、CBUS 引出；FT231X 支持专用充电器检测及枚举/挂起输出 | 可解决普通 USB 数据端口枚举预算，但需替换原板串口桥连接；在 MacBook USB-C 路径验证前不引入这项额外改造 |

### HUSB238：不能混淆输出开关与协商状态

[Adafruit 引脚指南](https://learn.adafruit.com/adafruit-husb238-usb-type-c-power-delivery-breakout/pinouts)说明 5 V 与 1 A 跳线默认闭合，数据引脚单独引出。[芯片数据手册](https://cdn-learn.adafruit.com/assets/assets/000/125/150/original/husb238_datasheet_full.pdf?1697209172)的 GATE PIN 段明确：默认在上电复位后打开外部开关；等显式合同成立再打开属于其他出厂配置。因此普通 #5807 的 V+ 出现 5 V 不能单独证明已经获得目标电流。还需核实具体出厂配置、状态读取或另加使能控制。暂不将这个功能差异转嫁给用户手动切换。

### PTN5150A：启动和输出已有原厂依据

[NXP 数据手册（模块厂家提供）](https://download.mikroe.com/documents/datasheets/PTN5150A_datasheet.pdf)第 7.1 节说明：无供电时仍以受电端呈现内部 Rd，可启动接入检测。第 6.2、7.5 节规定 PORT 接低电平为 UFP；ADR 悬空选择非 I²C 模式，OUT2/OUT1 表示检测到的电流等级：

| OUT2 | OUT1 | 检测结果 |
| --- | --- | --- |
| 1 | 1 | 默认 USB 电流 |
| 1 | 0 | 1.5 A |
| 0 | 0 | 3 A |

OUT1 在 1.5 A 和 3 A 两档均有效，具有作为充电输入控制信号的可能性。未连接、上电复位期间和声明变化时的输出不能只凭此表推定，必须继续核对时序并测量。所有输出为开漏，拉高电源、允许电平及掉电回灌需按芯片和模块电路分别检查。

[MIKROE 模块说明](https://www.mikroe.com/usb-c-power-2-click)和[原理图 v101](https://download.mikroe.com/documents/add-on-boards/click/usb-c-power-2-click/usb-c-power-2-click-schematic.pdf)给出 GPIO 模式跳线、外部 3.3 V 逻辑电源以及受电/供电两条路径。不能直接使用出厂跳线：需要固定 UFP、选择 OUT 模式、避免源供电通路，并确定如何从原 USB-C 接入 CC 和 VBUS。其控制电源不能来自受运行开关控制的 ESP32 3V3，否则无法独立完成关机充电和空电池启动。

### FT231X：普通 USB 的备用实现路径

[FTDI AN_175](https://ftdichip.com/wp-content/uploads/2020/08/AN_175_Battery-Charger-Detection-over-USB-with-FT-X-Devices.pdf)提供电脑和专用充电器自动充电实例：BCD# 指示专用充电端口，PWREN# 指示枚举完成且未挂起，SLEEP# 指示挂起。需要配置 MTP/USB 最大功耗及 CBUS 功能，而不是只连接两根 GPIO。全部 USB 电流包含桥芯片、系统和充电电流。

[SparkFun 原理图 v11](https://cdn.sparkfun.com/datasheets/BreakoutBoards/ft231x-breakout-v11.pdf)提供所需引脚访问，但部分 CBUS 接有 LED，配置前需断开对应跳线。采用它需要隔离原 CH340，改接 USB 数据、TX/RX、DTR/RTS，重新验证自动下载及关机时的 IO 回灌。因此它是有依据的备选，并非当前已选模块。

## 3. 外壳影响

原 80 × 88 × 42 mm 仅覆盖旧候选。MIKROE 模块额外占用约 1452 mm² PCB 投影面积，还带接线端子，不能只把它画成零厚度矩形塞进剩余空间。

冻结布局前必须选择：保留现成 CC 模块及其连接器包络，或制作更紧凑的控制小板。前者减少定制电路但增大壳体；后者涉及 PCB 制作和调试。仍保持一个外部 USB-C、一个运行开关，顶部沿用麦克风与 BOOT 的功能布局。

## 4. 下一步应获得的证据

1. 看清候选模块原理图的实际节点、跳线和电平，确定独立启动供电；不能只依赖产品营销表。
2. 确定原板 CC1/CC2 的可改焊位置及原 Rd，给出可执行的改造图。
3. 对选定电路列出插线前、检测中、电脑运行/挂起、充电器、低电量、拔线的硬件状态表，包括输入电流上限。
4. 完成模块实体包络与布局后再冻结最终外壳尺寸；现阶段没有电池版可打印模型。
5. 实测 MacBook 的 CC 电流声明、总输入和电池净电流，以及充电期间刷机。资料只能证明设计路径有依据，不能证明整机已达标。


## 5. 当前执行主机上的只读 USB 证据

见 [原始结果](2026-09-30-usb-readonly-evidence.json)。本轮在 IOUSB 注册表找到一个 WCH `1a86:7523` 设备，用 libusb 读取其当前配置；未打开设备句柄、未占用接口、未打开串口、未复位或刷机。它与照片开发板的对应关系尚未经独立确认。

- USB 版本字段为 `0x0110`，配置为 1，`bmAttributes=0x80`（总线供电）。
- `bMaxPower=49`，按此 USB 版本每单位 2 mA，申报最大电流为 **98 mA**。这不是实测耗电。
- 对应上游 AppleUSB20XHCIARMPort 的唤醒/休眠电流限制字段均为 **3000**，原始 `usb-port-current-limit` 字节为 `b8 0b 00 00`。这些是主机记录的限制属性，不能单独证明线上的 CC 电流声明或已经允许附件使用 3 A。

这项证据排除了“直接假设原桥芯片枚举申请了 500 mA”的依据。仅保持原 USB 描述符、不验证 CC 授权、却固定增加 500 mA 充电负载的方案不能由当前数据支持。继续调查独立 CC 检测是有证据的下一步；不能将实际找到串口设备误写成充电功能已经验证。

`system_profiler SPUSBDataType` 本次没有返回匹配条目，随后使用 IOUSB/IOService 注册表找到设备；前一个查询的空结果不能作为设备未连接的结论。
